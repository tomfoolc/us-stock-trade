## 決定草稿

1. **集中喺 Grok Bot + Cursor。** Grok 係唯一掂到晒檔案、repo、code 嘅 agent，做 PM（統籌）；Cursor 係唯一可以跑 Python、做 git 操作嘅地方。
2. **Perplexity 做研究員，唔做 PM。** 佢強在即時搜尋、財報、filings、有引用來源。唔用 API token 嘅情況下，佢經 GitHub Connector（Pro 已有）讀私人 repo，但寫唔返入 repo。
3. **Perplexity 用法：有需要先用人手跟進。** 流程：Grok 將研究問題寫入 repo `research/queue.md` → 用戶開 Perplexity，佢經 Connector 自己讀 repo → 答案出嚟，用戶一次過貼返入 repo（`research/answers/`）或者畀 Grok 存檔。由「每個 message 都 copy-paste」變成「每個研究任務貼一次」。
4. **GitHub 係唯一真相來源。** 規則、持倉、狀態全部以檔案為準；新 repo 用 2026-11-16 凌晨提出嘅 file structure（`rules/`、`state/`、`research/`、`decisions/`、`scripts/`、`data/digests/`、`docs/`、`logs/`），現有三份文件（v0.1、Strategy v1 草稿、工作表）搬過去，唔好留兩個版本。
5. **慳 Grok 用量靠檔案要細，唔係靠「放咗喺 GitHub」。** Grok 由讀成段長對話歷史變成讀短檔案：每日只寫一份 digest，`state/` 保持最新狀態，原始大數據放 PC／NAS 本地，唔塞入 git。
6. **Scraping／固定工作改由 PC／NAS 排程跑 Python。** 程式做手腳，Grok 只讀結果，唔再用 browser 逐頁撳。
7. **三個 Grok Bot，分工唔重疊：**
   - 個人助理 Bot（對人）：對話、接收決定、派任務、匯報進度。
   - 舊投資 Bot（顧問，凍結）：只按舊有規則畀意見，唔執行、唔改規則、唔寫新系統 state 檔；意見經用戶／助理 Bot 傳話，兩個 bot 唔直接溝通。
   - 新 Paper Trade Bot（執行者）：按 repo 確認咗嘅規則運作，做每日覆核同星期日覆核。Instruction prompt 已寫好，存喺 `新Paper_Trade_Bot_Instruction_Prompt.md`。
8. **Teamily 唔擺入呢個 loop。** 佢啱做多 agent 討論層，但冇公開 REST API／SDK，GitHub 寫入未核實；放多一個真相來源只會亂。Teamily Pro 收費另計：網頁版 US$199.99／月（年繳 US$159.99／月），經美國 App Store 訂係 US$289／月——用戶未講喺邊度訂，差價約 US$90／月有待確認。
9. **新 Bot 啟動條件（未滿足）：** 用戶確認 Strategy v1 草稿準確記錄規則，同埋決定星期日覆核用唔用 time-review ladder。未確認之前，新 Bot 只可以做準備，唔可以做交易判斷。
