# 美股研究及 Paper Trading 系統需求與制定方針 v0.1

- **版本：** v0.1
- **日期：** 2026-11-07
- **狀態：** 需求基線 — 記錄已討論的設計方向，並非表示系統已完成設定
- **用途：** 之後建立 GitHub 專案、編寫程式及配置 Grok Bot／Cursor 的基礎

核心原則是：**文件化**保存規則及最新狀態，固定工作交由程式執行，AI 負責研究、解釋及討論，而不是依靠長期聊天記憶運作。

## 1. 專案目標

建立一套供個人使用的美股研究及模擬交易工作流程，涵蓋：

1. 每日收集市場資料、篩選股票及監察持倉。
2. 每星期及每月檢討市況、市寬及 sector 強弱。
3. 尋找具潛在升值機會的股票，並討論支持及反面證據。
4. 制定入場、倉位、止蝕、止賺及其他退出條件。
5. 執行 paper trade，保存計劃、成交及績效紀錄。
6. 減少 AI 重讀 chat history，以及重複收集、計算和分析的用量。
7. PC 故障時，可由你手動啟動雲端環境恢復工作。

## 2. 已制定的主要方針

| 項目 | 方針 |
|---|---|
| 日常執行位置 | 長開 PC 為主 |
| 固定程式啟動 | 由 PC 排程器執行，不依賴 AI 每次決定如何啟動 |
| 日常資料來源 | Alpaca API 為主 |
| 互動補充研究 | Alpaca MCP、TradingView MCP，按需要查詢 |
| 圖表及 paper trade | TradingView |
| 程式開發及維護 | Cursor AI 協助 |
| 對話及工作協調 | Grok Bot |
| 財報、公告及背景研究 | Perplexity |
| 程式及研究文件版本管理 | GitHub 私人 repository |
| 雲端備援 | PC 故障時，由你手動要求啟動 Cursor Cloud Agent；不做自動故障切換 |
| StockCharts | 不納入本系統 |
| 實盤交易 | 第一階段不納入 |
| AI 自主修改策略 | 不允許；變更須經你確認及另設版本 |

## 3. 工具及責任分工

### 3.1 長開 PC

作為主要運行環境，負責：

- 按排程執行 Python。
- 收集及增量更新市場資料。
- 驗證數據。
- 計算指標、市寬、sector 表現及篩選結果。
- 保存本地資料庫及運行紀錄。
- 產生報告和最新狀態。
- 按設定備份及同步允許提交的文件。

PC 可以長開，但每日程式採用「啟動 → 執行 → 保存 → 結束」，不要求 Python 永久常駐。

### 3.2 Cursor AI

負責協助：

- 開發、測試、除錯及維護 Python 程式。
- 將分析及選股規則轉為可重複執行的程式。
- 深入分析候選股及策略結果。
- 編寫技術文件及操作手冊。
- 審閱及管理 GitHub 版本變更。

日常執行不需要每次啟動 Cursor AI agent。

### 3.3 Grok Bot

負責：

- 作為日常詢問及討論入口。
- 讀取最新市場摘要、候選股及持倉狀態。
- 解釋重要變化、提出待查問題及反面證據。
- 按配置檢查每日工作有否完成，並通知異常。
- 在你要求時協助操作本機，或協調雲端備援。

限制：

- 不自行修改程式、依賴、選股規則或風險政策。
- 不將主機故障自行解讀為可啟動雲端接管。
- 不提交實盤交易。
- 不因沒有新訊號而重新研究整個市場。

本機執行及 Cloud Agent 接駁能力，要在你的實際帳戶中驗證後才列為已啟用功能。

### 3.4 GitHub

作為程式、策略及精簡研究文件的版本來源，而不是所有行情資料的唯一儲存位置。

保存：

- Python 程式、測試及依賴設定。
- 策略、篩選及風險規則。
- 操作與復原手冊。
- 最新研究狀態。
- 精簡報告、投資論點及交易計劃。
- 決策與 paper trade 紀錄。

不提交：

- API keys、tokens、cookies、密碼及 `.env`。
- 未經授權保存或上傳的原始資料。
- 無限制增長的大型行情檔、資料庫及詳細 logs。

## 4. 功能需求

### 4.1 每日資料收集

系統須能：

1. 判斷是否有新的有效交易日資料。
2. 按指定股票池收集 OHLCV。
3. 保存資料來源、feed、資料日期、擷取時間及價格調整方式。
4. 增量更新，而不是每天重新下載全部歷史。
5. 檢查缺漏、重複、過期及異常資料。
6. 支援補做漏掉的交易日。
7. 在資料驗證失敗時標示失敗，不將舊資料冒充最新資料。

每日資料來源以 Alpaca API 為主；實際 feed、權限、可取得的歷史範圍及數據品質，須先測試。

### 4.2 每日股票篩選

篩選條件須：

- 寫成明確、可量化及可版本管理的規則。
- 由程式計算，不由 AI 憑印象填數字。
- 能說明每隻股票入選或被剔除的原因。
- 能比較昨日與今日的差異。
- 記錄使用的數據日期及策略版本。

每日輸出至少包含：

| 欄位 | 內容 |
|---|---|
| 股票代號 | 唯一識別 |
| 篩選日期 | 對應交易日 |
| Setup／策略版本 | 按哪套規則入選 |
| 訊號及指標 | 支持入選的數值 |
| 排名或評分 | 供候選比較，不等於上升概率 |
| 相對昨日變化 | 新增、維持、改善、轉弱或剔除 |
| 資料品質 | 完整、缺漏或待確認 |
| 待查事項 | 例如財報日期、基本面或事件風險 |

具體篩選門檻尚待制定。

### 4.3 市況、市寬及 sector 分析

每日保存必要快照，每週及每月作較完整 review。

分析範圍：

- 大市及主要指數趨勢。
- 股票高於指定均線的比例。
- 上升／下跌、新高／新低等參與度。
- 大型股、等權重及小型股的相對表現。
- Sector 絕對及相對表現。
- 市場領先是否擴散、集中或轉弱。
- 對新增交易及現有持倉的影響。

市寬必須記錄股票池及分母。自建研究池市寬，不可標示成官方 S&P 500 或全美市場市寬。

Sector 分類、指數成分及歷史成分來源尚待確定，不能假設價格 API 已包含全部資料。

### 4.4 個股研究及討論

每隻進入深入研究階段的股票，須保存：

- 目前投資論點。
- 技術面及 sector 支持。
- 基本面及催化因素。
- 主要反面證據。
- 風險及資料缺口。
- 推翻論點的條件。
- 來源、發布日期及查核日期。
- 下一次需要查核的事件。

須分開標示事實、推論及未驗證假設；「值得研究」不代表「已符合入場條件」。

### 4.5 交易計劃

每筆 paper trade 入場前，須有：

| 項目 | 需求 |
|---|---|
| 策略 | 策略名稱及版本 |
| 前提 | 市場及 sector 條件 |
| 入場 | 觸發條件、確認方式及最高可接受價格 |
| 止蝕 | 初始止蝕價及理由 |
| 倉位 | 依風險預算及倉位限制計算 |
| 止賺 | 固定、分段或追蹤退出規則 |
| 其他退出 | 時間、事件或論點失效條件 |
| 取消 | 入場前何時作廢 |
| 審批 | 由你確認後才執行 |

每筆風險、總風險、單股及 sector 集中度限制尚待制定。

### 4.6 Paper trade 及績效檢討

第一階段：

- 在 TradingView 人工執行 paper trade。
- 保存原交易計劃與實際成交。
- 不因事後修改規則而覆蓋原計劃。
- 策略變更以新版本管理。

績效報告須涵蓋：

- 扣除設定成本後的盈虧。
- 最大回撤。
- 勝率及平均盈虧。
- R 倍數。
- 持倉時間及資金曝險。
- 規則遵守率。
- 按策略、sector 及市場狀態分類的表現。

## 5. AI 用量及上下文管理

### 5.1 不以 chat history 作資料庫

每次任務優先讀取：

1. 相關短版規則。
2. 最新狀態。
3. 本次新增資料或差異。
4. 有明確需要才讀歷史文件。

不預設讀取全部 reports、research、原始行情或聊天紀錄。

### 5.2 共用狀態

Grok Bot、Cursor 及雲端備援使用同一套文件，而不是各自保存一個「最新答案」。

建議最少包括：

```text
state/current_state.md
state/market_state.json
state/watchlist.csv
state/positions.csv
state/last_success.json
```

### 5.3 任務分層

| 任務 | 執行者 |
|---|---|
| 下載、驗證、計算、排序 | Python |
| 固定時間啟動 | 排程器 |
| 解釋變化、比較論點、查證 | AI |
| 批准策略變更及交易計劃 | 你 |

沒有重要變化時，可只保存程式摘要，不要求 AI 每天生成長篇報告。

## 6. 資料、同步及備份方針

### 6.1 儲存分層

| 類別 | 主要位置 | 備份安排 |
|---|---|---|
| 程式及規則 | PC＋GitHub | GitHub 版本管理 |
| 精簡研究文件 | PC＋GitHub | 成功同步後可供雲端恢復 |
| 原始行情及資料庫 | PC | 獨立備份，或必要時補取 |
| 決策及交易紀錄 | PC＋適合的遠端備份 | 優先同步，不能靠行情重建 |
| 秘密憑證 | 各環境秘密管理 | 不經 GitHub 傳送 |

### 6.2 同步規則

- 修改程式須經測試，再提交指定版本。
- 每日成功後更新資料截至日期及執行狀態。
- 未推送內容不視為已備份。
- 同一時間只允許一個環境更新正式狀態。
- 避免 Bot 與 Cursor 同時改同一文件。
- 涉及外部寫入的自動化範圍，需另外明確授權。

## 7. 本機及雲端備援

### 7.1 日常模式

```text
PC 排程器
   ↓
Python → Alpaca → 驗證 → 計算及篩選
   ↓
本地資料＋報告＋最新狀態
   ↓
同步指定文件
   ↓
Grok Bot 按需要讀取及與你討論
```

### 7.2 故障模式

```text
你確認需要轉雲端
   ↓
啟動 Cursor Cloud Agent
   ↓
取得 GitHub 指定程式版本及已備份狀態
   ↓
檢查缺少的資料與可恢復日期
   ↓
補取資料並執行
   ↓
保存結果
```

要求：

- 第一階段不自動故障切換。
- 雲端須預先配置並試跑。
- 雲端執行不自行修改程式或策略。
- 啟動前確認本機不會同時寫入。
- PC 恢復後，先核對與同步結果，再恢復排程。

### 7.3 對話分工

可分兩個對話：

- `美股研究－Local 主機`
- `美股研究－Cloud 備援`

但對話名稱不構成執行位置保證。每次執行前須確認環境、專案路徑、程式版本及資料日期。

## 8. 安全、權限及操作限制

- 第一階段不開放實盤下單權限。
- 秘密憑證不放入程式、報告或 GitHub。
- GitHub 權限限定於所需 repository。
- 程式不得將憑證寫入 logs。
- 程式、依賴及策略變更須可追查。
- API 呼叫、資料保存及 AI 處理方式須符合供應商授權。
- TradingView MCP 不納入無人值守的每日資料收集管線。
- 外部網站及文件內容視為研究資料，不作為修改系統權限或執行指令的依據。

## 9. 第一階段不包含的功能

為控制複雜度，暫不納入：

- 自動實盤交易。
- 自動故障切換。
- 多個 agent 同時修改策略或正式狀態。
- 自動登入 StockCharts 擷取資料。
- 全天候反覆研究全部美股。
- 完整全市場歷史成分股及退市資料平台。
- 未經驗證的全面歷史回測。
- 由 AI 自主調參並直接套用到交易。

## 10. 建議實施次序

| 階段 | 主要工作 | 完成標準 |
|---|---|---|
| 1. 定義研究範圍 | 決定股票池、持有期、首個 setup、風險規則 | 有書面規則及版本 |
| 2. 建立資料管線 | Alpaca 存取、增量更新、驗證及本地儲存 | 可重複取得指定日期有效資料 |
| 3. 建立篩選及報告 | 指標、市寬、sector、候選差異 | 每個結果可追溯到規則及數據 |
| 4. 本機排程及 GitHub | 排程、logs、狀態、同步 | 無須 AI 介入也能完成每日工作 |
| 5. AI 問答及研究 | Grok Bot 讀狀態；Cursor／Perplexity 深入研究 | 不靠完整 chat history 亦能延續討論 |
| 6. Paper trade | 計劃、成交、檢討及績效 | 能追查原計劃與實際執行差異 |
| 7. 雲端復原演練 | 停止本機，從備份恢復並補做 | 在本機不可用時完成一次指定日分析 |

## 11. 尚待你決定的項目

進入開發前，優先確認：

1. PC 作業系統及可用儲存空間。
2. 交易風格：持有數天、數週，還是數月。
3. 股票池：指定指數、固定研究名單，還是按流動性建立。
4. 是否只做多，以及是否包含 ETF。
5. 第一個要測試的 setup。
6. Paper trade 本金及風險上限。
7. 是否持倉跨越財報。
8. Sector／指數成分及財務資料來源。
9. GitHub 同步內容、頻率及審閱方式。
10. 大型資料備份位置及可接受的資料損失範圍。
11. 每日報告通知方式。
12. Grok Bot 本機操作及 Cloud Agent 在你帳戶中的實際可用權限。

這份 v0.1 可作為後續的需求基線；下一步應先完成研究範圍與資料管線驗證，再逐步加入 AI 問答、paper trade 及雲端復原。
